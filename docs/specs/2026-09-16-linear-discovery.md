# Linear 스타일 곡 탐색 / 검색 추가 설계안

## 화면

- 첨부 이미지 기준: 거의 검은 바탕, 중성 회색 카드, 얇은 경계선, 상태 원형 아이콘, 보라색 주요 액션. 기존 차콜·앰버 시안 대체.
- 데스크톱: 모집 시작 / 모이는 중 / 완료 임박 / 모집 완료 보드. 그룹 목록 보기 전환 제공.
- 모바일: 같은 상태를 탭으로 전환하고 짧은 행으로 표시. 좌우 보드 스크롤을 요구하지 않는다.
- 곡 선택: 상세 대화상자. 실제 구현은 기존 파트 신청·댓글·재생·수정 기능을 보존한다. 시안은 집계 상세만 제공.

## 자동 단계 규칙 (제안)

사용자의 '1명 → 여러 명 → 임박'을 참여 증가로 해석했다. 구현상 단위는 중복되지 않는 사람 수가 아니라 정원 내 충원 자리 수다. 동일인이 여러 파트에 참여할 수 있으므로 최종 UI에서 '명'과 '자리'를 혼동하지 않아야 한다.

- 총 정원 0: 정원 미설정. 별도 접힌 그룹.
- 파트별 남은 자리 합 0, 총 정원 > 0: 모집 완료.
- 남은 자리 합 1: 완료 임박. 작은 편성에서도 이 규칙 우선.
- 남은 자리 > 1, 충원 자리 <= 1: 모집 시작.
- 그 외: 모이는 중.
- 한 파트의 초과 신청은 다른 파트의 빈자리를 메우지 않는다. 모집 완료와 공연/합주 완료는 별개.

## 곡 추가

곡 추가 → 서비스 탭 → 검색 → 결과 선택 → 자동 채운 제목·뮤지션·링크 확인과 파트 정원 설정 → 명시적 추가.

- 세 서비스의 결과는 섞지 않고 출처별로 표시. 라이브·커버·원곡 오선택 방지를 위해 아티스트/채널·썸네일·제공되는 길이 표시.
- 같은 서비스 ID/정규화한 URL 중복은 이미 추가됨 표시. 다른 서비스의 동명곡은 경고 후보로만 다루며 임의로 같은 곡으로 합치지 않는다.
- 결과 선택만으로 저장하지 않는다. 정원 확인 후 추가해야 실수 등록을 줄일 수 있다.
- 검색 중 / 결과 없음 / 인증 실패 / 할당량 초과를 구분한다. 오래된 검색 응답이 새 검색 결과를 덮지 않도록 한다.
- 시안은 예시 결과로 검색·선택·정원·추가 흐름만 동작. 외부 검색과 링크 저장은 미연결.

## 현재 코드와 연동 조건

- YouTube: 현재 /api/search-youtube는 검색 HTML에서 첫 videoId만 추출한다. 결과 목록용 API가 아니므로 그대로 연결하면 안 된다. 공식 Data API 검색 결과 목록을 사용하는 방안을 우선 검토하고 실제 키/할당량을 확인한다.
- Apple Music: developer token 생성 코드와 MusicKit 기반 내보내기 검색 코드가 있다. 재사용 가능성은 높지만 실제 토큰 유효성·카탈로그 검색 응답은 아직 검증하지 않았다.
- Spotify: 현재 링크 oEmbed 인식/내보내기 흐름과 카탈로그 검색은 별개다. 검색 endpoint와 서버 측 Client Credentials 경로를 마련하고 앱 접근 권한을 확인한다. 비밀키를 브라우저에 보내지 않는다.
- 이 기능의 저장 대상은 합주 앱의 곡 목록이다. 사용자 음악 서비스 플레이리스트 변경은 범위 밖.

공식 근거:

- https://developer.spotify.com/documentation/web-api/reference/search

- https://developers.google.com/youtube/v3/docs

## 시안 검증

24곡 스냅샷: 모집 시작 2 / 모이는 중 7 / 완료 임박 4 / 모집 완료 7 / 정원 미설정 4.
Playwright: 검색, 기타 빈자리 6곡, 예시 중복 비활성화, 예시 추가 후 25곡, 목록 전환, 모바일 상태 탭, 320/390/768/1500px 가로 넘침 없음. API 통합 검증은 미실시.
