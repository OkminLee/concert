# 구현 순서

1. 시안의 단계 의미·보드/목록·색감을 확정한다. 현재 산출물은 docs/design/linear-prototype.html.
2. 기존 변경 내역을 보존하며 파트별 충원 분류 함수를 분리하고 정원0·초과 신청·작은 편성 경계를 검증한다.
3. 기존 곡 신청/댓글/재생/검색/내 곡/일정/내보내기를 유지하며 데스크톱 보드와 모바일 그룹 목록을 연결한다. 모집 상태는 파생값으로 두고 드래그로 조작하지 않는다.
4. 세 서비스의 앱 자격 증명 존재·유효성을 비밀값 출력 없이 확인하고 읽기 전용 검색을 각각 시험한다. 필요한 설정만 별도로 요청한다.
5. 서버 검색 adapter → 공통 검색 결과 모델 → 출처별 검색 UI → 기존 곡 추가 API 연결 순으로 구현한다. 기존 링크 붙여넣기와 수동 입력은 유지한다.
6. 실제 저장을 하지 않는 검색 검증, 격리 데이터에서 추가/중복/정원/오류/구형 데이터 회귀, 모바일 터치/키보드/포커스/긴 제목을 검증한다.
7. 운영 적용은 변경 전 public 파일과 server.js의 정확한 스냅샷을 보관하고 진행한다. public 파일은 즉시 반영되므로 개발은 별도 디렉터리에서 완료한다. 복구는 그 스냅샷으로 변경 파일을 되돌리고 서버 변경이 있었으면 승인 범위 안에서 재시작 후 endpoint를 재확인한다. 곡 실데이터는 되돌리지 않는다.
