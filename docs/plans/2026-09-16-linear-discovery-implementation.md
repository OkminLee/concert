# 구현 결과와 운영 복구

## 구현

중성 회색·보라색 테마, 상태별 보드/목록, 파트 빈자리와 단계 필터, 정렬 기억을 연결했다. 기존 곡 상세 DOM과 이벤트를 유지하면서 상세 대화상자로 옮긴다. 상세를 닫으면 원래 그룹에 복귀하고 변경 없는 카드 DOM을 보존한다. 신청/취소/댓글/수정/일정/플레이리스트를 유지한다.

세 서비스 검색 → 정보 자동 입력 → 정원 확인 → 기존 곡 추가 API로 저장. 검색 출처·아티스트/채널·썸네일·길이를 표시하고 원본 듣기 링크를 제공한다. 검색어가 바뀐 뒤 도착하는 오래된 응답은 버린다. 서버는 인증·요청 제한·5분 캐시·동일 링크 중복 차단을 적용한다.

## Deviations

- YouTube는 공식 Data API 키를 새로 요구하지 않고 기존 HTML 검색을 ytInitialData 결과 목록 파싱으로 확장했다. 페이지 구조 변경에 취약하므로 파싱 실패를 빈 결과로 숨기지 않는다.
- Spotify는 기존 개인 앱의 Client Credentials로 읽기 전용 검색을 검증해 사용한다. 키는 저장소 밖 ~/.concert/spotify.json에 권한 600으로 보관한다.
- 상세를 카드 안에 길게 펼치면 보드 열이 길어지는 문제 때문에 대화상자로 옮겼다.
- 모바일은 전체 단계 그룹 목록과 단계 탭을 제공한다. 그룹을 숨기면서 내보내기 범위가 달라지는 혼동을 피하려고 필터와 내보내기가 같은 목록 조건을 쓴다.
- 기존 미커밋 일정/화면 변경은 8cd518f로 별도 보존했다.

## 복구

변경 전 사본: /Users/okmin/Work/concert-discovery-20260916/baseline.
그 사본의 public 디렉터리와 server.js/package.json만 복원하고 com.okmin.concert.server를 재시작한 뒤 공개 자산과 /api/songs를 재확인한다. 운영 data.json/members.json은 복원하거나 덮어쓰지 않는다. 추가된 검색 파일은 예전 index/server에서 참조하지 않으므로 즉시 지울 필요가 없다.

배포는 public 디렉터리의 원자적 교환과 서버 재시작으로 수행했다. 재시작 가드는 승인 마커를 별도 명령으로 만든 뒤 실행했다.

writing-well로 작성한 안내와 배포된 보드/검색 캡처 2장을 Slack #yb에 함께 게시했다. 채널 기록에서 메시지 1건과 image/png 첨부 2개·썸네일 생성까지 확인했다.

추가 회귀: 화면의 그룹/정렬 순서와 플레이리스트 내보내기 순서 불일치를 재현한 뒤 같은 순서로 정렬하도록 수정하고 Playwright 비교를 통과했다.

추가 요청: 카드 상세 바깥 클릭/터치로 닫기를 적용했다. 바깥에서 누르기 시작하고 바깥에서 클릭이 끝날 때만 닫는다. 데스크톱·모바일에서 외부 클릭/탭, 내부 클릭과 바깥으로 드래그, Escape/닫기 버튼, 원래 목록 복귀를 검증했다.
